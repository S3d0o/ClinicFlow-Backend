# R1 plan: "Clinic day", the first V2 release

| | |
|---|---|
| **Status** | Agreed 2026-10-29; nothing started |
| **Why** | The owner wants to present ClinicFlow to clinic owners and investors soon and offer it as a service. The full V2 (P0–P7) is too long a road to that, since P1 alone is 19 PRs. V2 now ships as **releases**. Each one is a working product, backend and frontend, that a clinic can use |

| **Builds on** | [P0](P0.md) (done), the agreed contract [API_CONTRACT.md §13](../../API_CONTRACT.md#13-planned-apiv2-endpoints-agreed-not-built), the frontend screens built on its mock, [ADR 0008](../adr/0008-multi-clinic-platform-module-entitlements.md) (Accepted with this plan) |

The V1 import tool (P1 PR 17) is built when a clinic that uses V1 signs up. It doesn't belong to any release.

**What the audience sees:**
- **Live product:** the real R1 app on a small VPS with HTTPS. Add-ons that aren't built yet are switched off by the clinic's plan, and opening one says "not in your clinic's plan".
- **V2 preview:** the frontend's mock-only build on GitHub Pages, labelled "Preview: sample data". It shows the R2–R4 screens (the doctor workspace, and later the finance screens) without pretending they are live.

## 2. Competitors (checked 2026-10-29)

Figures come from vendor pages. They show patterns, not reliable prices.

|---|---|---|---|
| Kind | Clinic system with a WhatsApp bot | Patient marketplaces with practice tools | Clinic systems with EMR |
| Price | 799 / 1,599 / 3,299 EGP a month per clinic, plus a 2,500 EGP setup fee. Extra doctor 249, extra branch 799, extra TV screen 149, fertility add-on 349, import from 1,500 | Not published | Trial; usage-based |
| Strengths | WhatsApp booking with an AI bot; numbered queue and TV screen; patient files, invoices, inventory, lab requests; reports per doctor; dental, physiotherapy and fertility workflows; up to 3 branches on Pro | Patient demand (listing, reviews), video consultations, installments (CliniDo with Fawry and Souhoola) | Scheduling, EMR, billing, WhatsApp, multi-branch, an AI assistant |

**Only ClinicFlow has:**
- doctor recruitment
- insurance with the co-pay split, pre-authorizations and claims
- nurse triage
- an EMR with ICD-10, a prescription allergy check, signing and addenda
- cash sessions, daily close and an approvals inbox
- roles per branch with permissions and staff MFA
- an audit trail that can't be edited
- modules sold one at a time

R1 already has the triage, cash-session, approvals, branch-role and audit parts.

**Both have:** appointments, a queue TV, WhatsApp reminders, invoices, a dashboard and reports, Arabic and English, an online booking page.

**Gaps:**

| Gap | What to do |
|---|---|
| Booking by chatting on WhatsApp (Tabbaba's lead feature) | Roadmap slide: R4's BOT, extended to WhatsApp conversations (Q16) |
| Specialty workflows (dental tooth chart, physiotherapy courses) | Roadmap slide. Dental is a large segment in Egypt; candidate for an add-on after R2 |
| Inventory | Out of scope on purpose ([01 §4](../01_VISION_AND_SCOPE.md#4-scope)) |
| Importing old Excel or paper records | Offer it as a paid onboarding service, as Tabbaba does |
| Marketplace demand, video calls, installments | A different business; partners, not features |

- visits and visit summary → EMR
- documents → EMR
- insurance → INS

Deposits show only when the organization setting enables them.

## 4. Milestones

Each milestone ends with a checkpoint you can present. Every milestone runs the loop already used for the front desk:
1. Build any missing screen on the frontend mock.
2. Add its shapes to contract §13 (a backend docs PR) and mirror the contract to the frontend.
3. Build the backend PRs. They implement §13 unchanged.
4. Write the frontend's HTTP adapters for those services.
5. Walk the checkpoint.

### M0: a preview link now (frontend only)

| PR | Changes |
|---|---|
| `chore/demo-persistent-mock` | `src/mocks/persistence.ts` saves the mock database to `localStorage` on `pagehide` and every 5 s, and drops the copy when the seed version or the day changes, or when it can't be parsed. `files` and `queueListeners` aren't stored. Every storage call is wrapped in try/catch. `main.tsx` loads it. "Reset demo data" goes through `DemoAccountsService`. Tests for the round trip, the day change, the version bump and broken JSON |
| `chore/preview-github-pages` | `.github/workflows/pages.yml` runs on every push to `v2`: `npm ci`, `npm test`, `npm run build` (mock backend), then deploy to Pages. A `noindex` meta tag and a "Preview: sample data" ribbon. The owner sets Pages → GitHub Actions once in the repo settings |

**Checkpoint:** the preview link opens on a phone and a laptop, and a booking survives a reload.

### M5: ship R1

## 5. Presentation scripts

**Clinic owner (about 12 minutes, in Arabic, on the live app):**
1. On a phone, the patient finds a doctor, sees the price, books, and gets the confirmation message.
2. The receptionist checks the patient in and adds a walk-in. The waiting-room TV updates.
3. The nurse records the vitals.
4. The doctor calls the patient in and completes the visit.
5. The receptionist takes the payment and prints the receipt.
6. The manager closes the day, then opens the dashboard.
7. The admin opens "Plan & modules": switching Starter → Clinic shows what each plan unlocks.
8. Open the preview link to show the doctor workspace, insurance and finance as "next".
9. End on the price compared with Tabbaba, per clinic, and the onboarding service.

**Investor (about 8 minutes):**
1. The same flow, shortened to steps 1, 2, 5 and 6.
2. Slides:
   - the market and the competitors (§2)
   - what only ClinicFlow does
   - per-module pricing and the add-ons (ADR 0008)
   - releases R2–R4, the WhatsApp booking bot and dental workflows
   - the architecture: one platform, tenancy, the outbox and audit, the tests enforced in CI
